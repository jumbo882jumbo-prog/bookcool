## 1. User Personas

การออกแบบระบบอ้างอิงจากตัวแทนกลุ่มผู้ใช้งานจริง 3 กลุ่มหลัก:

### Persona 1: คุณสมชาย (พนักงานออฟฟิศสายพัฒนาตนเอง)
* **ชื่อ-นามสกุล:** นายสมชาย พัฒนาตน (อายุ 32 ปี)
* **อาชีพ:** ผู้จัดการฝ่ายการตลาดดิจิทัล (Digital Marketing Specialist)
* **ความเชี่ยวชาญด้านไอที:** ปานกลางถึงสูง ใช้งานสมาร์ทโฟนและคอมพิวเตอร์เป็นประจำ
* **เป้าหมาย (Goals):**
  - ต้องการหาหนังสือแนวธุรกิจ กลยุทธ์สตาร์ทอัพ และ AI สำหรับนำมาปรับใช้กับงาน
  - ต้องการสั่งซื้อง่าย จ่ายเงินผ่าน Mobile Banking (QR Code) ได้ทันใจ
  - ได้รับไฟล์ E-Book อย่างรวดเร็วหลังจากโอนเงินเรียบร้อย
* **ปัญหาที่เคยพบ (Pain Points):**
  - ร้านหนังสือบางร้านต้องกรอกข้อมูลส่วนตัวยาวเหยียด
  - ไม่รู้ว่าจ่ายเงินแล้วคำสั่งซื้อถึงขั้นตอนไหน รอตรวจสอบนานโดยไม่มีสถานะแจ้ง
* **User Scenario ใน Bookcool:**
  - สมชายเปิดหน้า `index.html` พิมพ์ค้นหา "Startup" ในช่องค้นหาแบบเรียลไทม์
  - กดดูรายละเอียดและคลิก "ใส่ตะกร้า" จากนั้นไปหน้า `checkout.html` สแกน QR Code จำลอง
  - อัปโหลดสลิปโอนเงิน แล้วเฝ้าดูสถานะ "รออนุมัติ" ในหน้า `my-books.html` เมื่อแอดมินอนุมัติก็คลิกดาวน์โหลดได้ทันที

---

### Persona 2: น้องกัญญา (นักศึกษาสายอ่านนิยายและความรู้ทั่วไป)
* **ชื่อ-นามสกุล:** น.ส. กัญญาภัทร รักษ์การอ่าน (อายุ 21 ปี)
* **อาชีพ:** นักศึกษาชั้นปีที่ 3 สาขาเทคโนโลยีสารสนเทศ
* **ความเชี่ยวชาญด้านไอที:** สูง ถนัดการใช้งานบนอุปกรณ์พกพา (iPad, Smartphone)
* **เป้าหมาย (Goals):**
  - เลือกซื้อ E-Book วรรณกรรม นิยาย และคู่มือไอทีที่มีราคาคุ้มค่า
  - ค้นหาหนังสือตามงบประมาณได้ง่าย (คัดกรองตามหมวดหมู่และเรียงราคาจากน้อยไปมาก)
  - อ่านรีวิวและเรตติ้งดาวจากผู้อ่านคนอื่นก่อนตัดสินใจซื้อ
* **ปัญหาที่เคยพบ (Pain Points):**
  - เว็บไซต์โหลดช้า บนมือถือจัดหน้าไม่สวย ปุ่มกดเล็กและกดยาก
  - อ่านหนังสือบนแท็บเล็ตแล้วไฟล์ไม่พร้อมให้ดาวน์โหลด
* **User Scenario ใน Bookcool:**
  - กัญญาเปิดเว็บผ่าน iPad เลือกแท็บหมวดหมู่ "# วรรณกรรม & นวนิยาย"
  - ใช้ปุ่มจัดเรียงราคา "ราคา: ต่ำไปสูง" เพื่อเลือกซื้อเล่มที่คุ้มค่า
  - เข้าหน้า `reviews.html` เพื่อดูความคิดเห็นของผู้อ่านท่านอื่นก่อนตัดสินใจซื้อ

### Persona 3: พี่อาทิตย์ (ผู้ดูแลร้านค้าและจัดการหลังบ้าน - Store Admin)
* **ชื่อ-นามสกุล:** นายอาทิตย์ จัดการดี (อายุ 38 ปี)
* **อาชีพ:** ผู้ดูแลระบบร้านค้า E-Book และนักวิเคราะห์ข้อมูล
* **ความเชี่ยวชาญด้านไอที:** สูง เชี่ยวชาญการใช้โปรแกรมบริหารจัดการและภาษา SQL
* **เป้าหมาย (Goals):**
  - ตรวจสอบความถูกต้องของสลิปการโอนเงินของลูกค้าได้อย่างรวดเร็ว
  - กดยืนยันคำสั่งซื้อเพื่อปลดล็อกไฟล์ให้ลูกค้าได้ในคลิกเดียว
  - ตรวจสอบยอดขายรวม สถิติหนังสือขายดี และเขียน SQL วิเคราะห์แนวโน้มธุรกิจ
* **ปัญหาที่เคยพบ (Pain Points):**
  - ข้อมูลคำสั่งซื้อไม่ซิงค์แบบเรียลไทม์ ต้องคอยกดรีเฟรชหน้าบ่อยครั้ง
  - ดูรูปสลิปแล้วภาพแตก หรือไม่มีระบบแจ้งสถานะบิลที่รอดำเนินการ
* **User Scenario ใน Bookcool:**
  - อาทิตย์ล็อกอินด้วยบัญชีแอดมิน เข้าหน้า `admin.html`
  - ตรวจดูรายการบิลที่ขึ้นสถานะ "pending" คลิกเปิดดูภาพสลิปขนาดใหญ่
  - กดยืนยันคำสั่งซื้อ (Approve) บิลจะเปลี่ยนสถานะเป็น "approved" อัตโนมัติ
  - สลับไปหน้า `reports.html` และ `sql-console.html` เพื่อติดตามกราฟยอดขายรายวัน

## 3. ผลตรวจความสามารถในการเข้าถึง (Accessibility Audit)

### 3.1 มาตรฐานและเครื่องมือที่ใช้ตรวจ
* **มาตรฐานการประเมิน:** **WCAG 2.1 Level AA (Web Content Accessibility Guidelines)**
* **เครื่องมือประเมินผล:**
  - Google Chrome Lighthouse (Accessibility Category)
  - axe DevTools Accessibility Linter
  - WebAIM Contrast Checker

### 3.2 ผลคะแนนการตรวจประเมิน (Lighthouse Score)

| หน้าจอที่ประเมิน | คะแนน Accessibility | สถานะผลประเมิน | จุดเด่น |
| :--- | :---: | :---: | :--- |
| `index.html` (หน้าร้านค้า) | **96 / 100** | 🟢 ดีเยี่ยม (Pass) | คอนทราสต์สีชัดเจน, มี Alt text ครบทุกรูป |
| `book-detail.html` (รายละเอียด) | **98 / 100** | 🟢 ดีเยี่ยม (Pass) | มีโครงสร้างหัวเรื่อง `<h1>` - `<h3>` ถูกต้อง |
| `cart.html` (ตะกร้าสินค้า) | **95 / 100** | 🟢 ดีเยี่ยม (Pass) | ปุ่มเพิ่ม-ลดจำนวนรองรับ Keyboard Focus |
| `checkout.html` (ชำระเงิน) | **95 / 100** | 🟢 ดีเยี่ยม (Pass) | Form Labels ชัดเจน, คำอธิบายฟิลด์ครบถ้วน |
| `my-books.html` (คลังหนังสือ) | **97 / 100** | 🟢 ดีเยี่ยม (Pass) | มี ARIA Status Badge บอกสถานะคำสั่งซื้อ |
| `admin.html` (หน้าแอดมิน) | **94 / 100** | 🟢 ดีเยี่ยม (Pass) | Modal ดูสลิปรองรับปุ่ม Esc และ Focus Trap |

### 3.3 รายการตรวจสอบตามเกณฑ์ WCAG 2.1 Level AA (Checklist Matrix)

| รหัสเกณฑ์ | รายละเอียดเกณฑ์ (Criterion) | ผลการตรวจ | วิธีการที่นำมาใช้แก้ไขใน Bookcool |
| :--- | :--- | :---: | :--- |
| **1.1.1** | **Non-text Content:** สื่อที่ไม่ใช่ข้อความต้องมีคำอธิบาย | ✅ PASS | ใส่แอตทริบิวต์ `alt="ชื่อหนังสือ"` ให้รูปหน้าปกทุกเล่ม และ `alt="หลักฐานสลิปโอนเงิน"` สำหรับรูปสลิป |
| **1.3.1** | **Info and Relationships:** โครงสร้างข้อมูลเชิงความหมาย | ✅ PASS | ใช้ Semantic HTML5 Tags: `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<button>` |
| **1.4.3** | **Contrast (Minimum):** อัตราส่วนคอนทราสต์ข้อความไม่ต่ำกว่า 4.5:1 | ✅ PASS | ใช้สีตัวอักษร `#1e293b` บนพื้นหลัง `#f8fafc` (Contrast 13.8:1) และปุ่มสีน้ำเงิน `#1d4ed8` บนขาว (Contrast 7.1:1) |
| **2.1.1** | **Keyboard:** ทุกองค์ประกอบต้องกดเข้าถึงได้ผ่านคีย์บอร์ด | ✅ PASS | ปุ่มและลิงก์ทุกจุดใช้ `<button>` / `<a>` แท้ สามารถกด `Tab`, `Enter`, และ `Space` ทำงานได้ |
| **2.4.7** | **Focus Visible:** แสดงเส้นโฟกัสชัดเจนเมื่อใช้คีย์บอร์ดนำทาง | ✅ PASS | กำหนด CSS `focus:ring-2 focus:ring-blue-500 focus:outline-none` ชัดเจนบนทุกปุ่มและช่องกรอกข้อมูล |
